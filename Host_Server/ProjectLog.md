# Day1:完成了摄像头的图像采集和显示问题

对于图像采集时，对于在Jetson上直接采集显示视频流是不可实现的，因为是Headless开发，无法将视频推送到显示器上显示。于是采用UDP将视频流推送到主机上显示。推送后发现帧率低和画质损失的问题，前者是因为硬件默认YUYV格式传输，由于USB带宽有限，导致视频帧率下降，故采用MJPEG的格式发送图像数据，帧率问题得到很好的解决，但是画质损失问题更加的严重，由于两次的JPEG压缩，导致图像的细节损失更加严重。后经过分析，发现现在的“encode-decode-encode”模式，是画质问题的元凶（两次JPEG压缩），且导致了视频处理过程的效率很低。我们可以将上述的模式优化为“encode”一步，直接在USB数据缓冲区读取图像数据，然后通过UDP推送。这是以后的一个优化点。

今天还初次尝试了RetinaFace，挫败感很重。这比我之前的接触的网络结构要复杂许多，唯一欣慰的是还是在其中看到了许多的熟悉面孔。初步拜读了RetinaFace的论文，也不能说毫无收获，它教会我不要上来直接啃论文。今天算是摸索出来一点学习方法和前进的方向：

2. 去啃模型代码，了解模型的架构和各个层的原理和作用，以及各个层之间的连接关系，也就是从细节把握。

3. 拜读一下论文，再强化一下学习的成果，查看遗漏的实现细节和设计巧思。

开始的过程一定是痛苦的，学习的过程就是将那些晦涩难懂的东西变得熟能生巧。世上无难事，只要肯攀登。走的慢无所谓，这是为以后的快打下基础，只要保证前进就行，按照上面的计划前进下去吧！fighting!

# Day2:完成了RetinaFace的python推理环节和整体把握了网络原理

今天就是验证了那句：“凡事都有一个接受和理解的过程”，在day1对推理环节和网络原理完全摸不着头脑，像看天书一样的感受一去不复返。今天整体把握了网络的原理流程。对于输入和输出有了更深的理解。接下来总结下，今天遇到的问题和学习到的新知识点：

1. 首先通过编写的test_output函数对输出进行一个数据维度上的分析。[1,N,4],[1,N,2],[1,N,10]。

2. 就是对RetinaFace的anchor有了更加深刻的理解，anchor就相当于取代了mtcnn中卷积滑动的操作，加上min_size的框，就相当于取代了mtcnn中图像金字塔的操作，通过不同step锚定的anchor值以及对应的min_size框，实现了对图像中大小脸的检测。==对于两种操作（特征金字塔和图像金字塔）的效率问题是我们之后的课题之一==。在实现anchor的priorBox函数的时候，我发现了两个重要的细节，这对我们理解RetinaFace有着重要的作用。对于取锚定anchor时，我们对特征图的分块进行了向上取整`feature_x=ceil(img_width/step)`,这里理论上存在一个越界的问题。还有在step=32时，划分256和512大小的框的时候，也明显存在越界问题。但是在原理设计中，这种越界是被允许。也正是这样的越界，才能识别那些在图像边缘的人脸。==只是注意在cv画框的时候进行clip截断操作==。
3. 接着就是对torch.cat（在dim指定的维度上进行延申，这个维度本来就是存在的，进行拼接操作的tensor数组的其他维度应该保持一致的大小），torch.stack（在dim位置创建一个新的维度以达到拼接，拼接的tensor数组的所有维度都应该保持一致大小）
4. decode函数就是通过公式将实际的cx，cy，w，h算出来，返回x1，y1，x2，y2（归一化值），之后要乘以图像宽高恢复实际坐标，==注意取整==
5. 输入图像需经过“减去平均值-更换维度-转tensor-送至gpu”

# Day3:进行了代码解耦和结构优化，以及解决了RetinaFace推理错误的bug

为了降低代码的耦合度，降低后期维护更新的难度，对代码进行一次解耦和结构的优化，使得代码模块化程度更高。

接着修复了推理错误的bug。bug来源于先验框与模型输出的box顺序不对应。在修复priorBox函数实现的时候，进一步掌握了关于tensor的维度变换的操作。新学了==view==和==expand==函数的使用方法。view是将具有contiguous属性的tensor进行形状变换的函数,它返回一个新的tensor视图，只是对原先的tensor进行不同形状的数据解读，不具有新的独立地址，当然要求最后的tensor元素总大小一致。expand函数是将原先维度大小等于1的维度进行任意大小的拓展（拓展的数据与原先数据相同），但这也是逻辑上的延拓，新延拓的数据不具有实际物理存储空间。
